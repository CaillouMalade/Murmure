# V0.3.0 requested scope

Arthur requested quick dictation triggered by configurable keys or a command, insertion at the active text cursor after recording/processing, delightful animation, Markdown output in a chosen folder, and optional automatic summarization through Codex CLI or Claude Code using a template he defines.

He clarified that he wants only a small dynamic indicator, then processing and insertion when finished, with clipboard copying as an option. Recognition must be selectable, with SSH the default. The visual reference supplied in chat is a black rounded capsule with six white vertical bars, with a thin dark outline. Implement that as a native menu-bar view rather than adding a web runtime or model to the app.

Quick dictation is a typing action. It does not trigger automatic CLI summaries or export every utterance to the notes folder. Its saved recovery data remains accessible through the recording history. Long recordings get the Markdown/export/summary workflow; automatic handoff starts off and applies only to new recordings for which it was enabled. An interrupted handoff is retried manually, avoiding duplicate provider usage.

The [official OpenAI dictation/voice guidance](https://developers.openai.com/training/walkthroughs/using-voice) distinguishes converting speech into editable prompt text from a voice conversation. [Codex Micro's documented hold/release flow](https://learn.chatgpt.com/docs/features/codex-micro) confirms processing before the prompt is ready and a separate send action. These sources do not establish a global system-wide Codex shortcut or the exact application animation; Arthur's screenshot is the visual reference. Murmure inserts text without pressing Return or submitting it.

CLI commands are based on [Codex non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode), its [command reference](https://learn.chatgpt.com/docs/developer-commands?surface=cli), and the [Claude Code reference](https://code.claude.com/docs/en/cli-reference). The app uses an existing CLI executable/login, sends text through stdin without a shell, runs in a fresh temporary directory and captures the summary as Markdown. No provider API key, paid inference test or account setup is required to build this integration. Actual provider calls begin only when the user invokes or enables the feature on their Mac.

Local dictation uses Apple's speech framework only when it supports on-device recognition for the selected language, with requiresOnDeviceRecognition set. It fails clearly rather than sending audio to Apple's servers. SSH dictation uses a foreground request after recording stops; deferred long-recording jobs keep the existing detached worker flow. Native cursor insertion needs Accessibility permission and preserves the target/selection. A changed or secure target must not receive text.

Build v0.3.0, preserve the earlier tags, and record automated and real-Mac verification separately. The bot runs on Windows. Native capture, cursor insertion, shortcuts and smoothness still require Mac checks even when the package builds and native indicator snapshots render in CI.
